Cogware Personal

Privacy Policy

Private financial reconciliation application

Version: 1.0 (personal pilot)   ·   Last Updated: November 22, 2026

1. About Cogware Personal

Cogware Personal is a privately operated financial reconciliation application for a single authorized operator. It is in personal user-acceptance testing, not a publicly available service.

Cogware Personal is independently developed and is not affiliated with, endorsed by, or supported by YNAB.

2. Information accessed

When you explicitly authorize it, Cogware Personal requests read-only access through the official YNAB OAuth API. It may retrieve budget plan settings and metadata; account names, types, and balances; categories and monthly category activity; and transactions, including dates, amounts, payees, transfers, and category assignments.

The application is intended to reconcile one plan selected by the operator. YNAB may also return limited metadata for other plans visible to the grant during plan identification and revision checks; Cogware uses that metadata only for those checks.

Cogware does not request bank-login passwords and does not write changes to YNAB or ProjectionLab in this pilot.

3. How information is used

Cogware uses the retrieved information to reconcile accounts and spending, identify transfers and exceptions, and present read-only financial summaries for operator review. No automatic updates are made to YNAB or ProjectionLab.

For the initial personal test, the operator selects one plan and a bounded reporting period. Unsupported or incomplete evidence is identified rather than automatically treated as verified.

4. Storage and retention

During requested operations, YNAB financial data and reconciliation previews are processed locally in memory. The initial pilot does not automatically keep a persistent financial-data cache or automatically export reports.

OAuth refresh credentials and any locally retained application secret are stored in a dedicated, nonsynchronizing macOS Keychain. Access credentials are managed by the approved local connection workflow. Stored connection credentials remain until removed through the local disconnect or deletion process.

A local acknowledgment record stores the accepted notice version, policy version, and acknowledgment time, not the underlying financial records or credentials. It remains until reset or deleted.

Reports, screenshots, files, and previews that the operator separately saves or copies are not automatically deleted by Cogware and must be managed separately.

5. Sharing and external services

Cogware Personal does not sell YNAB information and does not knowingly pass YNAB financial data to third parties without separate disclosure and authorization. OAuth authorization and API requests are transmitted to YNAB. The initial pilot does not automatically send retrieved financial records to hosted AI services, analytics providers, ProjectionLab, or cloud storage.

This policy is intended to be hosted as a static webpage on GitHub Pages. GitHub may process normal website connection information under its own policies; the policy page itself contains no YNAB financial records or authentication credentials.

6. Security

Cogware's personal pilot is designed to use read-only authorization, an explicitly approved local workflow, a dedicated macOS Keychain, and scoped credential cleanup. Local access controls and operating-system security remain important. No system can guarantee absolute security.

Any material expansion in data use or disclosure will require updating this policy and renewed acknowledgment or consent before activation.

7. Disconnect, deletion, and retention controls

Deletion method for this private single-operator pilot: The sole authorized user is also the operator and can request and carry out removal directly through the documented local Cogware Finance cleanup commands. Close any running Cogware connection session, open the established Finance package environment, and use the command matching the desired scope:

python3 -B -m cogware_finance.ynab_cleanup disconnect --production
python3 -B -m cogware_finance.ynab_cleanup delete-local --production
python3 -B -m cogware_finance.ynab_cleanup delete-local --production --remove-app-secret

Disconnect removes local stored authorization tokens, while retaining the acknowledgment record and application secret. Delete local removes the local connection data and resets acknowledgment but preserves the application secret by default. The third command removes that secret too, and requires an additional explicit confirmation. Review the outcome of each operation; if any deletion step fails, it remains outstanding and must not be represented as complete.

The complete live cleanup workflow must be verified before the personal pilot is enabled. Do not include credentials or financial records in deletion or support requests.

Local cleanup does not revoke authorization held by YNAB; revoke the application separately in YNAB's authorized-applications settings. Records retained by YNAB or ProjectionLab and copies saved independently by the operator must also be managed separately.

8. Changes to this policy

When Cogware Personal changes which categories of YNAB information it accesses or how that information is used or shared, this policy will be updated and renewed acknowledgment or consent obtained before the new processing begins.

9. Privacy and deletion requests

This pre-release version is restricted to a single operator. The local cleanup procedure in Section 7 is the operator's deletion-request and fulfillment method. A dedicated external contact method and customer-facing deletion process will be established and this policy updated before public availability.

10. Third-party services and attribution

Cogware Personal uses the YNAB API with authorization from the account owner. Cogware Personal is not a YNAB product. The privacy-policy webpage is intended to be published through GitHub Pages.

This policy is separate from the mandatory YNAB third-party acknowledgment notice, which must be displayed and acknowledged by the application.
